# Change Management

When a business rule changes, update implementation, tests, metrics doc, decision stream and current state once live.

When architecture changes, update current-system/integration/deployment docs and structured context.

Do not erase superseded approaches; record them as superseded/paused so the agent does not rediscover and re-propose them.

Version complete user-visible packages. Historical reference versions:
- single-phase free v1.2
- priority update v1.3
- dual-phase Central v1.4
- Playwright prototypes v0.1/v0.2/v0.3

Current-state docs say what is true now. Decision docs say why. Historical artifacts are not current requirements.
